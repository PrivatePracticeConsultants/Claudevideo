Hospital comparison — what this payer pays the hospital

CMS makes every hospital publish its negotiated rates. Loading the local hospital's file shows what the SAME payer pays the outpatient department for the SAME codes. A hospital rate is a facility rate — it pays for the department, not a private practice's professional fee — so it is evidence of what this payer already pays in this market, never an amount you are owed.

Against Medicaid and workers' comp

Load your state's Medicaid and workers'-comp schedules (any CSV with a code column and a rate column) to show what sits under and over a commercial rate. "Your commercial rate is 4% above Medicaid" ends an argument faster than a percentile does. These are your uploaded numbers — the app never fetches or invents a Medicaid rate, and a code a schedule omits is left out, never treated as zero.

Walk-away leverage — how badly does this payer need them?

How many OTHER therapy practices this payer publishes rates for near your client, and how many seniors those alternatives would have to absorb. A thin local network is the strongest argument in the room. Published rates mean a contract, not that a practice is open or taking patients — so the real number of usable alternatives is smaller, which makes the leverage bigger, not smaller.

What a visit is worth

Owners don't think in "$44 for 97110" — they think in what a visit pays. This prices the practice's own Medicare code mix against each payer. The mix is Medicare fee-for-service only, and Medicare counts units rather than visits, so the units-per-visit divisor is your assumption and is printed as one.

New to network — just-signed practices

Practices in a payer's published book this month that were absent from that payer's previous published month. A practice that just signed its first commercial contract is the strongest lead in this data: new to negotiating, and probably took the opening offer.

Brand-new clinics — before they sign anything

Therapy NPIs the NPPES file says were ISSUED recently. A clinic enumerated last month has no payer contracts yet — the earliest a rate consultant can reach it. Needs the NPPES monthly file loaded once (Files tab → bulk enrichment).

Closures nearby — a referral source gone, or a competitor gone

Therapy NPIs the NPPES file says were DEACTIVATED recently and not since reactivated. A closed referral source is a hole in a client's inbound volume they should hear about from you first; a closed competitor is room in the market. NPPES deactivates for paperwork lapses and mergers too, so treat every row as a call to make, not a fact to print. Needs the NPPES monthly file loaded once.

Referrals going to someone else

Physicians who send therapy patients to other practices in your client's own city — and little or nothing to your client. Every other list here finds practices; this one finds the specific relationship to go and win. Needs a CMS referral release imported on the Medicare tab. Shared-patient counts are a proxy for referral, not a record of one, so these are the calls worth making first — not proof a relationship is winnable.

Paste file links — the app does the rest

Paste one or more links (one per line): direct rate files (.json.gz), a payer's Table of Contents / index link (it will be opened and every file inside queued automatically), or even a plain file-listing page. Downloads and processing run in the background — several files at a time, scaled to your machine.

Two kinds of source. Auto-queueable ones load with the "Queue tested payer indexes" button (or paste the link). Portal (open in browser) ones build their file list with JavaScript behind a search form or bot-check, so they can't be queued directly — open them yourself and paste the file links. How: click the payer name to open its page → follow the Notes for that row (accept any terms, pick a plan/state if asked) until you see a list of files ending in .json, .json.gz, or .zip → right-click each real file (or the "Table of Contents"/"index" link) → Copy link address → paste them into the "Paste file links" box above. One Table-of-Contents link is enough; the app expands it into every rate file inside.
